# Attacks attempted

## Citation check

**FAIL — verbatim mismatch.** The docstring at `ComputableAnalysis/L1/ComputableSeqReal.lean:362` says *"Pour-El & Richards Ch. 0:55, Definition 2. A real number `x` is computable iff the constant sequence `fun _ => x` is a computable sequence of reals."* The blueprint env at `blueprint/src/L1.tex:87` repeats *"P-R Ch.\,0:55, Definition 2."* The `current-goal.md:57` criterion text also says *"P-R Ch. 0:55 citation"*. All three are wrong:

- Line 55 in `literature/papers/PourEl-Richards-chapt0.md` is the body of the displayed equation inside **Definition 2**, which is *about effective convergence of a sequence to a real number*, not about computable real numbers.
- The actual P-R definition our predicate corresponds to is **Definition 3** at **line 58**: *"A real number x is computable if there exists a computable sequence {r_k} of rationals which converges effectively to x."*
- The phrasing *"the constant sequence is a computable sequence of reals"* is not in P-R at all. The P-R Definition 3 is about a *single* rational sequence converging *effectively* to x (with explicit modulus `e(N)`). Our definitional unfolding goes via Definition 5a — i.e., this is a *derived equivalence* tracing back through Def 4 + Def 1 + the implicit Def 5 ↔ Def 5a folding, not a direct restatement of any single P-R definition. The docstring presents it as a direct restatement, which it is not.

The misattribution is uniform across docstring, blueprint, goal text, and the C6 criterion description — strong evidence this was copied from an earlier note and never verified against the verbatim file. P-R also gives the constant-sequence characterisation (a single element is computable iff its constant sequence is) in the *introduction* (intro:7, per CLAUDE.md commitment #2), not in Ch. 0.

This is the kind of citation error a Mathlib reviewer would flag immediately ("which definition number, please?"). It is not a soundness bug; it is a faithfulness bug — but the file's whole reason for existing is to be a faithful port.

## Hypothesis weakening

- **Drop the constant-double-sequence form, replace by a literal P-R Def 3 transcription.** A faithful encoding would be: `IsComputableReal x := ∃ r : ℕ → ℚ, IsComputableSeqRat r ∧ ∃ e : ℕ → ℕ, Computable e ∧ ∀ N k, k ≥ e N → |((r k : ℝ)) − x| ≤ 1/2^N`. The current `IsComputableSeqReal (fun _ => x)` form is provably equivalent (use `r_k := s(0,k)` for one direction; embed `r` as `fun (n,k) => s(unpair k).2` for the other, with the `e` modulus folded into Def 5a) but the equivalence is exactly the Def 5 ↔ Def 5a content that this very file's `What this file is NOT` section at line 64 calls out as deferred. So claiming `IsComputableReal` faithfully matches P-R Definition 3 without that equivalence in hand is overstated.
- **Drop the `(fun _ => x)` reduction and re-state at the point level directly.** A point-form predicate `∃ r : ℕ → ℚ, IsComputableSeqRat r ∧ ∀ k, |((r k : ℝ)) − x| ≤ 1/2^k` (Def 5a applied at a point, no `n` index) would compose more naturally with downstream point-level arithmetic. Our chosen form is correct but carries a vacuous `n` index through every elimination. Future `IsComputableReal.add` will have to discharge `Nat.unpair`-noise that a point-form predicate would not.
- **Drop `.ofRat` lemma.** Conclusion is still true (it's a corollary). Lemma is genuinely useful for downstream callers, but it is the *only* downstream-facing API surface for the def shipped in this round (see "Specific fixes" §3 below).

## Counterexample hunt

No mathematical counterexample to the predicate's correctness — it is provably equivalent to P-R Definition 3 (modulo classical real-equality reasoning). Fragile spots:

- **Equivalence with Definition 5/5a applied at a single n.** The constant-double-sequence form `r(n,k) := <approximant of x at precision 2^{-k}>` works fine because `x` is constant in `n`; the witness `r(n,k) := s k` (a *single* rational sequence ignoring `n`) suffices when `s` already satisfies `|s k − x| ≤ 1/2^k`. But `IsComputableDoubleSeqRat` requires the *pair-encoded* form is computable, i.e., `IsComputableSeqRat (fun n => r (Nat.unpair n))`. For a constant-in-first-coord `r(n,k) := s k`, the pair-encoded form is `fun n => s (Nat.unpair n).2` — computable iff `s` is computable and `Nat.unpair` is computable (it is, via Mathlib's `Primrec.unpair`). So the equivalence holds but requires invoking the `IsComputableSeqRat.comp` lemma shipped earlier in this same file. The unfolding chain is not exhibited anywhere — neither in `.ofRat` (which short-circuits via the constant case) nor in a Def 3 ↔ our-def lemma.
- **Step that would break under perturbation:** if the prior `IsComputableSeqReal.const_rat` lemma's witness were not the *literally constant* double sequence `fun _ => q` but something more elaborate, the proof `theorem ofRat (q : ℚ) := isComputableSeqReal_const_rat q` would still type-check (since the goal is definitionally `IsComputableSeqReal (fun _ => (q : ℝ))`), so the `.ofRat` lemma does not exercise the `IsComputableReal`-vs-`IsComputableSeqReal` boundary in any meaningful way. It is purely a renaming. That is fine but means C6's "sanity lemma" requirement is satisfied very thinly.

# Quantifier / edge / completeness checks

- **Quantifier order in the def is `∃ r, … ∧ ∀ n k, …` (inherited).** No `∀ε ∃δ` reversal — the modulus is the second index, not existentially quantified per-precision.
- **Edge case `x = 0`.** Predicate is satisfied: take `r(n,k) := 0`. `IsComputableSeqRat (fun n => 0)` follows from `isComputableSeqRat_const 0`. Bound is `|0 − 0| = 0 ≤ 1/2^k`. Fine.
- **Edge case `n = 0` (smallest index).** `IsComputableSeqReal (fun _ => x)` evaluated at `n = 0` gives `x` — no degenerate behaviour.
- **Edge `k = 0` (no precision).** Bound `|r(n,0) − x| ≤ 1` — non-vacuous, but always satisfiable by floor(x).
- **Completeness.** Two `"clearly"`-shaped gaps:
  1. The docstring asserts the def *is* P-R Definition 2 [sic — should be Definition 3]. The equivalence with the literal Def 3 modulus form is never demonstrated. Per `claims/l1-computable-reals/is-computable-seq-real.md:94` this is the known-deferred "Def 5 ↔ Def 5a" gap, plus the additional Def 3 ↔ Def 5-at-a-point gap (which is even thinner — folding the modulus into the second index at a fixed `n`).
  2. There is no `Iff` lemma `IsComputableReal x ↔ IsComputableSeqReal (fun _ => x)`. The def is currently a `def`, so the unfolding is definitional, which is fine ergonomically — but the absence of an explicit unfolding lemma means downstream proofs will need either `show IsComputableSeqReal (fun _ => x)` rewrites or `unfold IsComputableReal` calls. A simp lemma `IsComputableReal.iff_seq` (or making the def `abbrev`) would be cleaner. Note: `abbrev` would conflict with the sorry policy line 125 ("Forbidden: `def` / `structure` / `class` / `instance` / `abbrev` bodies [with sorry]") — but that policy is about *sorry in the body*, not about choosing the keyword, so `abbrev IsComputableReal := …` is permitted. A `def` is defensible (predicates are usually `def`-not-`abbrev` in Mathlib so the term doesn't unfold automatically and bloat the goal state), but the choice is not documented.
