Hi all — I'm formalizing Pour-El & Richards' *Computability in Analysis and Physics* (Cambridge UP, 1989) in Lean 4, and I'd value a sanity check on the headline design before building further. The choice is deliberately **predicate-first** rather than represented-spaces / TTE flavored: computability is a `Prop`-valued predicate on sequences of *pre-existing* Mathlib types, not a parallel category of "computable spaces". There is no new `ℝ_c` — `IsComputableSeqReal : (ℕ → ℝ) → Prop` lives on Mathlib's own `ℝ`, and a `ComputabilityStructure 𝕜 E` typeclass adds the predicate on top of any Banach space `[NormedAddCommGroup E] [NormedSpace 𝕜 E] [CompleteSpace E]`. The mental model is Mathlib's own `Continuous : Prop` vs `ContinuousMap`: the predicate is primary; bundled subtypes are additions, not replacements, only where ergonomics demand. The substrate is Mathlib's existing `Computable` / `Partrec` on `ℕ` — no oracle TMs, no Type-2 / Baire-space realizers in the public API. One thing I'll flag up front: `IsComputableSeqReal` is morally `Nonempty (realizer)`, so a `Type`-valued, data-carrying layer (exposing the modulus / index explicitly) can be layered on later as a refinement without re-architecting — the predicate is its propositional truncation.

Where it stands — **L0** (recursion bridge to `Computable`; P-R Prop B effective separation), **L1** (`IsComputableSeqRat` / `IsComputableSeqReal`, closure under arithmetic + `max`/`min`/`abs`, P-R Ch. 0 Prop 1 lifted as `isComputableSeqReal_of_effectiveConvergence`), **L3** (the `ComputabilityStructure` typeclass), and the first **L4** instance `C(Set.Icc α β, ℝ)` with the sup-norm — are all `sorry`-free, with `#print axioms` returning `[propext, Classical.choice, Quot.sound]`. For the L4 instance, all three P-R Ch. 2 axioms (Linear Forms, Effective Limit, Computable Norm) are individually proved, parameterized by an explicit rational bound `B ≥ max(|α|,|β|)` and computable-real witnesses for the endpoints. That endpoint hypothesis is load-bearing, not cosmetic: without it an empty `Set.Icc α β` admits adversarial coefficients that defeat the norm bound (P-R Ch. 2 makes the same "for recursive reals `a, b`" restriction). Code: <https://github.com/YssnBkd/mathlib4-computable-analysis>; blueprint + dep graph: <https://yssnbkd.github.io/mathlib4-computable-analysis/blueprint/>. I'm aware of Mathlib's own `Mathlib.Computability` (`Computable` / `Partrec` / Turing machines) and of represented-spaces work in other proof assistants (e.g. the Coq `Incone` library); I'd love to know if there's *Lean-specific* prior art on computable analysis I've missed.

My headline question: **is the predicate-first shape — `IsComputableSeqReal : (ℕ → ℝ) → Prop` on Mathlib's `ℝ`, over the `Computable` / `Partrec` substrate — the right surface for upstream, or should the public API instead expose a represented-space / realizer layer (Pauly / Brattka tradition) and recover the P-R predicates as a corollary?** Closely related: how visible should Weihrauch-degree machinery be at the surface? I have narrower follow-ups (computability of *points* via the constant-sequence trick; `Computable` vs `Partrec` as the default substrate; whether the L4 instance's six explicit hypotheses are too heavy for review), but I'll keep those for a follow-up so this thread stays focused. I'm treating this as a standalone Mathlib-adjacent project that upstreams reusable pieces (e.g. computable-reals lemmas) incrementally rather than landing the whole edifice at once — a reality check on *that* framing is welcome too.
