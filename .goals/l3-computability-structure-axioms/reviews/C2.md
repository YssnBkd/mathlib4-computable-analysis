# Restatement

The claim defines an L3 `ComputabilityStructure` typeclass on a Banach space `X` over a scalar field `K` (real or complex). The structure is the data of a predicate `IsComputableSeq : (ℕ → X) → Prop` subject to four conditions: (A1) closure under finite linear forms with computable scalar double sequences and recursive truncation index `d : ℕ → ℕ`; (A2) closure under effective limits (effectively in `k` and `n`, in the sup norm); (A3) the map `(x_n) ↦ (‖x_n‖)` reaches down into L1's `IsComputableSeqReal`; and (NV) non-vacuity, formalized as `zero_seq : IsComputableSeq (fun _ => 0)`. A computable point is a point whose constant sequence is computable. The artifact is `our_construction` because the formal shape (predicate, four typeclass fields) is the project's formalization choice; the substance is verbatim from Pour-El & Richards Ch. 2 §1. The claim also includes formalization remarks (commentary, non-axiomatic) and rationale notes flagging that uniqueness requires effective separability — not (A1)–(A3)+(NV) alone.

## Hypothesis weakening

- **Drop (A1):** Loses closure under linear combinations. The (NV) derivation also fails (it depends on A1 to instantiate the zero sequence). Not redundant.
- **Drop (A2):** Loses effective-limit closure — completeness is unexploited. Not redundant.
- **Drop (A3):** Loses the L1 reach-down (no way to extract numerical norms). Not redundant.
- **Drop (NV):** The empty predicate `IsComputableSeq := λ _, False` vacuously satisfies (A1)–(A3). P-R explicitly excludes this at chapt2.md:77. Not redundant.

The four conditions are independent. The claim does not over-claim independence; it states each axiom and the (NV) clause as separate fields, which is the standard P-R treatment.

**Weakening the effective-convergence definition:** if we replaced "‖·‖ ≤ 1/2^N for k ≥ e(n,N)" with pointwise/uniform convergence, (A2) would no longer guarantee L1 computability of the limit — Specker-style examples (chapt0.md:147–165) demonstrate. The modulus is essential, as P-R emphasizes.

## Counterexample hunt

The user-flagged trivial-everywhere-zero predicate (`IsComputableSeq x := ∀ n, x n = 0`) satisfies all four axioms:

- (A1): closing zero sequences under linear combinations of zero × zero gives zero. Verified.
- (A2): an effective limit of the everywhere-zero double sequence is zero. Verified.
- (A3): `‖0‖ = 0`, and the constant-zero real sequence is L1-computable. Verified.
- (NV): the zero sequence is the predicate's only inhabitant; (NV) holds. Verified.

This is the canonical pathological structure. The claim explicitly discloses this at line 114 with the exact predicate spelled out: "the *counterexample* `IsComputableSeq := fun x => ∀ n, x n = 0` (the trivial-everywhere-zero predicate) satisfies all three axioms on any `X` but captures none of P-R's intended content."

I also probed other candidate counterexamples:

- "All-rational-coordinates" predicate on `X = ℝ`: fails (A1) because computable real scalars can be irrational. Not a counterexample to (A1)–(A3)+(NV) holding simultaneously; instead, it's a non-example.
- "Pointwise-computable" predicate (each `x_n` is individually computable, no uniform program): fails (A1) because pointwise computability does not pass through `s_n = Σ α_{n,k} x_k` uniformly in `n`. This is exactly the L1 distinction at chapt0.md:178–184 between pointwise and sequence-uniform computability.

The disclosure of the trivial-everywhere-zero structure is adequate. A future reader can reproduce the counterexample directly from the claim's inline disclosure.

## Fragile-step probe for the (NV) equivalence

The forward direction (`∃ x → zero_seq`) applies (A1) with:

- `(x_n), (y_n) := x, x` (the witness from the existential — typing is fine even though we reuse the same sequence twice)
- `α_{n,k} = β_{n,k} = 0` (the all-zero double sequence of scalars)
- `d(n) = 0`

This gives `s_n = Σ_{k=0}^{0} (0 · x_0 + 0 · x_0) = 0` (a single-term sum that evaluates to 0).

For the all-zero scalar double sequence to be a valid input to (A1), it must be a *computable* double sequence. For `K = ℝ`: the everywhere-zero rational double sequence is computable (Def 1 with `a = 0`, `b = 1`, `s = 0`), and any constant-zero real sequence satisfies Def 5a trivially (take `r_{n,k} = 0`). For `K = ℂ`: the coordinatewise extension is also zero, hence computable. Likewise `d(n) = 0` is the constant-zero recursive function. All inputs check out. The argument is sound.

The reverse direction (`zero_seq → ∃ x`) is trivial: `(fun _ => 0)` is the existential witness.

# Minor stylistic gap (not a defect)

The L1 stub at `claims/l1-computable-reals/is-computable-seq-real.md` defines `IsComputableSeqReal` and `IsComputableSeqComplex` only as single-sequence predicates (`ℕ → ℝ` and `ℕ → ℂ`). Axiom 1 of the L3 claim references "computable double sequences of scalars". The Cantor-pairing decoding from single to double sequences is convention in P-R (chapt0.md:189) and is stated for the X-valued case in the L3 claim at line 33, but is not explicitly stated for the scalar case (reals/complex) in either the L1 stub or the L3 claim. A careful reader can infer this via the uniform pairing convention from chapt0.md:189, which the L1 stub cites at lines 40–42.

This is a one-line refinement opportunity (e.g., add "the double-sequence version of these scalar predicates is via the same Cantor-pairing decoding" to the formalization remark at line 108). It does not affect soundness — the convention is universal across P-R's framework — but a future Lean implementer will benefit from the explicit statement. I am noting this as a stylistic refinement, not a blocking defect.
