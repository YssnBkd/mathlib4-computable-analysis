# Restatement

For a constant computable real `c : ℝ` and a Grzegorczyk-Lacombe-computable
continuous function `f : C(Set.Icc α β, ℝ)`, the scalar product `c • f` is
again GL-computable. The sequential-computability clause reduces to
`IsComputableSeqReal.mul` applied to the constant sequence `fun _ => c`
(equivalently `IsComputableReal c`) and the output sequence `fun n => f (x n)`.
The modulus clause uses an arithmetic upper bound `M := Mc 0 ≥ |c|`
(extracted via the new `IsComputableSeqReal.bound` lemma) to amplify `f`'s
modulus: `d_smul N := df (N + M)`, with the bound chain
`|c|·|f x − f y| ≤ M · 1/2^(N+M) = M/(2^N · 2^M) ≤ 1/2^N`, the last step
using `M ≤ 2^M` from `Nat.lt_two_pow_self`. The two L1 supporting lemmas
provide (a) a Computable Nat-valued upper bound on any computable real
sequence (via the rational approximant at precision `k = 0` plus a triangle
inequality with cushion `+1`), and (b) closure of `IsComputableSeqReal` under
pointwise multiplication (with modulus `e(n,N) := N + Ma n + Mb n + 1`,
amplifying both witness sequences by their magnitude-bound budgets).

## Hypothesis weakening

### `IsComputableSeqReal.bound`

- **Drop `b_w ≠ 0` (`hne_w`)?** Then `a_w/b_w` could be `0` (Mathlib's `1/0 = 0`)
  but `(-1)^s · 0 = 0`, so `ry(n,0) = 0` would force `|y n| ≤ 0 + 1 = 1` — but
  `y n` could be anything. The witness equation would be a lie because the
  numerator-denominator decomposition only matches when `b_w > 0`. The
  hypothesis is essential. Cannot weaken.
- **Replace `+ 1` cushion in `M(n)` by `+ 0`?** Then `M(n) = a_w + b_w`. The
  triangle gives `|y n| ≤ |ry(n,0)| + 1`, so we need the `+ 1` somewhere.
  Could shift: take `M(n) = a_w + b_w + 1` (current) or `M(n) = a_w + 1`
  (tighter) or even just `M(n) = ⌈a_w/b_w⌉ + 1` (tightest). All work; the
  current `+ b_w` is a harmless add (since the bound is just `Computable
  Nat upper bound`, not "tightest"). Not a bug.

### `IsComputableSeqReal.mul`

- **Replace `+ 1` shift in modulus `e(n,N) := N + Ma n + Mb n + 1` with `+ 0`?**
  Then the bound chain needs `(Ma + Mb)/2^k ≤ 1/2^N`, i.e.
  `(Ma + Mb) · 2^N ≤ 2^k`. With `k = N + Ma + Mb`, need `(Ma + Mb) ≤ 2^(Ma + Mb)`.
  True (`Nat.lt_two_pow_self` minus 1). BUT the numerator from `h_RS + h_bR`
  is `(Ma + 1) + Mb = Ma + Mb + 1`, NOT `Ma + Mb`. So `+ 1` in the modulus
  is correct and load-bearing; weakening to `+ 0` would leave a `1/2^k`
  residual that the `Nat.lt_two_pow_self`-amplification cannot absorb at
  small Ma, Mb. Not weakenable.
- **Use `|R| ≤ Ma n` instead of `|R| ≤ Ma n + 1`?** No — `R` is an
  approximant to `a n`, so `|R| ≤ |a n| + |R − a n| ≤ Ma n + 1/2^k`, and at
  large `k` this is `≤ Ma n + ε`. The strict `Ma n` bound would only hold for
  `|R| ≤ |a n|` plus error, which isn't a clean inequality. The `+ 1`
  cushion is essential.

### `l2_smul_gl`

- **Drop `IsComputableReal c`?** Then no `Mc` bound (nothing to extract
  magnitude from) and no `hc_seq` for clause (i). Cannot proceed.
- **Drop positivity on `hf`'s modulus?** Then the conclusion's
  `∀ N, 0 < df (N + M)` can't be derived; the positivity witness is
  essential.
- **Use `M := Mc 1` instead of `Mc 0`?** Works identically — both bound `|c|`
  since `c` is constant. Choice of `0` is convention. Not a bug.

# Non-blocking notes

1. **Choice of `M := Mc 0` is arbitrary.** Any `Mc n` works (since `c` is
   constant, all `Mc n` bound `|c|`). The `0` index is harmless; no need to
   change. Could add a clarifying comment.

2. **The modulus `df (N + M)` is loose for small `c`.** When `c` is small
   (e.g., `c = 1/100`), `Mc 0` could still be 1 (the rational approximation
   at precision 0 says `|1/100 − ry(0,0)| ≤ 1`, so `ry(0,0)` could be e.g.
   `0`, and `M = 0 + 1 + 1 = 2`). The modulus `df (N + 2)` is then mildly
   inflated. Not a soundness issue, just sub-optimal — a tighter bound would
   use `⌈|c|⌉.toNat + 1` directly (as the original C4 hint suggested) but
   that adds Computable-of-ceil + cast plumbing that isn't worth the gain.
   The simpler `Mc 0`-based approach is correct and clean.

3. **`bound` could be tightened to `M(n) := a_w + 1`** (drop `b_w`); the
   `b_w` term is unused in the final inequality (`a_w + 1 ≤ a_w + b_w + 1`
   uses `b_w ≥ 0`, but we already have `a_w/b_w ≤ a_w`). However, keeping
   `b_w` in `M` is a defensive choice and `Computable.nat_add` is trivial.
   Not worth changing.

4. **No use of `hs_w`** in `bound` (the sign Computable). The proof only
   needs the numerator/denominator structure, not the sign — `|(-1)^s · q| =
   |q|` collapses the sign regardless of computability. The underscore in
   `obtain ⟨a_w, b_w, s_w, ha_w, hb_w, _hs_w, hne_w, heq_w⟩` correctly notes
   this. No issue.

5. **Comment at line 416 says "clause (i)" but the sequence is at line 417**
   ("hc_seq : IsComputableSeqReal (fun _ => c) := hc"). The `def`-unfolding
   from `IsComputableReal c` to `IsComputableSeqReal (fun _ => c)` works
   transparently (Lean's elaborator unfolds `def`s during type-checking).
   No issue, but a future reader might wonder; a tiny comment "unfolding
   IsComputableReal = IsComputableSeqReal (fun _ => c)" could help.

6. **The `l2_smul_gl` proof's `h_eq` for clause (i)** uses `funext n; show
   (c • f) (x n) = c * f (x n); simp [...]`. The `show` line is between two
   syntactic forms — `(c • f) (x n)` (LHS displayed as `c • f (x n)` by
   `simp`'s view) and `c * f (x n)`. This works because `ContinuousMap.smul_apply`
   normalizes `(c • f) (x n)` to `c • f (x n)`, and `smul_eq_mul` turns
   `c • f (x n)` into `c * f (x n)`. Clean.
